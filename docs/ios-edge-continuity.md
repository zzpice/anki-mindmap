# Alpha.12：iOS 翻面时保持边栏分界和标签位置

起点为 feat/react-rewrite / cbbe701。用户确认：只在 iOS 的部分卡片翻面时，文字和上下边栏分界都会向下移动。这次保留 alpha.11 的窄边栏、横排换行文字、原生图片手势和轻量动效，不再更改视觉设计。

## 证据和适用边界

当前四块固定按钮使用百分比上下边界，标签居中。所以固定定位参考高度从 780 变成 844 CSS px 时，分界会下移 32px，上方标签下移 16px，下方标签下移 48px。Chromium 与 WebKit 均能复现。此前等高正反面测试漏掉了这一条件。

这证明模板在参考高度变化时的行为，尚未直接测得用户手机上的尺寸，也不能断言所有 iOS 下移均由同一种原因引起。对本地目标笔记的只读检查没有发现 Text 内嵌 script/style，不能把问题归给旧笔记脚本。

AnkiMobile 开发者[说明](https://forums.ankiweb.net/t/empty-area-between-image-and-bottom-bar-wastes-screen-real-estate-ankimobile/62258/20)：WebView 延伸到整个屏幕，原生栏与内容 inset 会影响可见区域。这是不要用普通浏览器窗口或固定扣除若干工具栏像素冒充手机客户端布局的依据；该历史说明不是本次实机根因证明。

## 改动

- 只对识别为 iOS 的客户端启用。平台识别复用 platform.ts；Android、Desktop 保持原布局。
- 正面记录四块按钮实际测得的几何，与既有阅读位置、展开状态一起交接给当前卡背面。通过同一份卡源签名、原生 ordinal、过期时间、单次消费和宽度校验，避免跨卡沿用。
- 背面保持正面的分界和文字锚点。新增的底部空间仅延长下方背景和点击区域；下方标签因此保持正面锚点，而非在新增长度中再次居中。这是为翻面稳定性作出的明确取舍。
- 转屏或窗口宽度变化、用户主动改变复习缩放时取消锚定，恢复常规 CSS 排版；新卡、新 ordinal 不继承。只发生高度变化时不重新计算分界。
- 不使用整屏 vh/svh 换算、工具栏固定像素补丁、新共同定位框或循环滚动监听。CSS zoom 的像素换算只针对已测得的按钮坐标，不改变正文。
- 存储不可用、数据损坏或按钮数量不符时回退常规 CSS，不能阻止复习。

## 代码关系

src/edges.ts 只管理呈现几何；src/continuity.ts 负责原有的单次正反面交接；runtime.tsx 协调挂载、投影、保存和清理。core.ts 不变，业务状态没有第二份权威实现。监听器归当前卡资源作用域，卸载移除；临时 inline 样式同步清理。

runtime.inspect().edgeLayout 提供是否启用／是否锚定及当前视口尺寸，便于后续诊断，不收集或上传数据。

## 回归与限制

tests/react/edges.cjs 专门模拟 780→844 的正反面视口变化，检查分界、文字锚点、底部触控区、滚动、复习缩放、转屏、切卡、不同 ordinal、损坏和禁用存储。原有 100 轮生命周期测试增加 iOS 路径，验证事件与资源不会残留。

手机实机仍须复测。若是原生可见区域整体平移、初次开卡就定位错误、或会话存储被客户端隔离，这份几何交接不一定覆盖；不能用浏览器通过替代 iOS 认证。iPad 仅改变窗口高度时会优先保持锚点；改变宽度或主动缩放可恢复自适应。未改变 Anki 的翻面、评分、字段、笔记或复习记录。

本地最终验证：官方 Anki 25.9.2 / 26.9.3 的构包与兼容性检查、9 项业务测试、两种引擎各 54 个原生正反面样例及各 100 轮 iOS 路径生命周期检查、Anki Desktop 26.9.3 隔离资料的 54 个预览面和 5 步 reviewer 测试均通过。最终机器记录见 test-packages/verification.json；iOS 实机结论仍待复测。
