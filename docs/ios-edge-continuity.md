# iOS 边栏：撤回无效补偿，测量后再修

**Alpha.13 没有宣称修好 iOS 翻面下移。** 用户对 alpha.12 的重复实机反馈仍然失败，因此删除该版本新增的坐标缓存。不会继续增加冻结位置、延时重算或工具栏像素补丁。

## 已确认的事实

- 对照来源是最新 `origin/main f67c932a`；工作起点为 `feat/react-rewrite b47c3639`。
- main 原版也用百分比 fixed 定位。模拟视口高度从 780 变为 844 时，原版和 React 的左侧分界都会从 390 变为 422。**这只是浏览器对照，不能断言原版在用户的 iPhone 上也有问题。**
- alpha.12 的旧测试先卸载正面，再改变视口高度。改为先变高度、再卸载时，它会保存已经移动的坐标，背面即使标记为 pinned，分界仍移动 32px。这是已复现的实现缺陷，不是实机根因证明。
- 受授权的本机只读核对确认：上次写入的模板与运行时资源一致。40 条实际笔记各抽一张卡，其原生正反面在 Chromium / WebKit 中均能匹配源、ordinal 和节点结构；未发现正文内嵌 script/style。未修改、上传或打包这些个人内容。
- 尚未测得 iOS 故障发生时的窗口高度、可见视口偏移、宿主布局或会话存储行为，所以不能判断是宿主可见区域变化、固定定位参照变化，还是另一条客户端路径。

## 整套代码检查后的处理

检查范围包括 core、content、React UI、runtime、输入适配、正文阅读定位、正反面交接、平台、公式、资源、呈现时序和动效模块。

| 发现 | 处理 |
| --- | --- |
| 边栏同时受旧皮肤、数轮 CSS 覆盖、JS inline 坐标控制 | 删除 edges.ts 及交接字段；style.css 一处定义当前边栏几何；旧皮肤中的离屏/竖排/比例规则删除 |
| 每次 scroll/touch 中断都递增无人读取的 intent，通知 React | 删除 intent；中断只取消自动定位并合并记录阅读位置，不改变业务 store |
| 标题、搜索显隐和按钮间距靠重复覆盖 | 归回各自的样式定义；普通历史标题、正文视觉和已确认的紧凑顶部标题保持 |
| 已删除的填写笔记弹窗仍留样式，键盘处理有重复分支，UI 接收未用 side | 清理这些残留；字段、字段内容与其他功能保留 |
| 业务状态/正文/React/资源的基本边界仍成立 | 保留，不重新拆一套架构；全部输入继续走统一命令；答案与树不互相修改 |

正文阅读锚定仍是有限时、可取消的呈现逻辑，与被删除的边栏坐标冻结不同。其跨面匹配限制见 reading-layout.md。没有把未知 HTML 归一化，也没有自写 Cloze 分卡规则。

## 一次独立实机对照

[下载 main / React 边栏对照 APKG](../test-packages/anki-mindmap-layout-comparison.apkg)。它含两组完全相同的匿名样例，共 14 条笔记、14 张卡。原有短树、深树、宽表格答案和普通图片保留；新增三个长图样例，分别放在两版的「长图复现」子牌组，方便直接进入，不必先翻短样例。独立模型 ID 为 1792748514 / 1792748524，既不更新正式模型，也不更新普通 React 测试模型。重复导入和保留既有模型/字段/排程的检查由官方 Anki 临时集合执行。

两张长图都是 720 × 8400 像素的真实本地 PNG，分为 A01–A12 / B01–B12 十二段，末尾标有「图片结束」。没有用空白占位或强制页面高度充当长图。三个场景分别是：

- **01 长图始终可见**：正反面都有长图，先滚到中段、底部，再翻面。
- **02 点击挖空或翻面**：前面有多层正文，当前答案是一张不预设尺寸的长图，覆盖揭示后页面变长的情形。
- **03 连续两张长图**：两张图之间有正文和当前挖空，末尾继续有正文，可在上部、中部、底部分别观察翻面。

390 × 780 手机视口下，长图实际显示高度约 3600–3740 CSS 像素，最长页面约 9800 CSS 像素，超过十二屏。Chromium / WebKit 检查正反面、上中下滚动、当前长图答案触控揭示与收回，以及无外部请求。**这些是浏览器样例证据，尚未证明 iPhone 上的边栏故障已复现或修复。** 本轮只延长对照内容，没有改动运行时、日常模板或个人集合。

1. 导入后只测试「Anki Mindmap · 边栏对照（独立样例）」里的卡，不转换真实笔记类型。
2. 进入 main → 长图复现，正常复习，滚到长图中部、底部后翻面；点「布局数据」查看正面记录与当前坐标。不要只用预览代替日常复习。
3. 退出并彻底关闭 Anki，再进入 react → 长图复现，测试相同样例。旧版 main 没有现代卸载机制，重开客户端是为了排除它遗留的全局处理器干扰对照。
4. 若出现移动，保留该卡正反面和「布局数据」的截图或复制文字即可。记录只有视口、滚动和边栏尺寸，不含答案内容、不联网、不改变边栏位置。若样例不能复现，应明确记录没有复现，不能据此关闭问题。

原版只替换测试模型身份和等价本地媒体路径，模板业务代码保持 pinned main 内容；字体与旧版辅助脚本均使用独立的带摘要文件名，导入不会覆盖已有同名旧媒体。诊断按钮放在额外测试模板中。React 正常构建没有此诊断代码，也不引用 main 的旧脚本。

复现构包与对照：在 README 的正常构建后依次运行 prepare_visual_comparison.py、build_layout_comparison.py、node tests/react/layout-comparison.cjs。机器记录见 test-packages/verification.json 和 layout-diagnosis.json。浏览器新增检查覆盖两种卸载顺序、真正尺寸变化时的自适应、等高正反面稳定与无 inline 补偿，不再把「固定不动」的模拟结果作为手机通过证明。
