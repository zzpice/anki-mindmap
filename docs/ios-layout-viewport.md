# alpha.14：边栏高度与节点圆点

这次处理两个独立问题，不改变树、答案、搜索的业务规则。

## 展开其他分支后，边栏变长

用户在 iOS 的 alpha.13 原卡上提供了新的复现步骤：正面展开「截位法」「加法」等其他分支，边栏分界和文字随之下移，并不需要翻面。截图里的数值为 CSS 像素：

| 同一张卡的状态 | 根元素 clientHeight | innerHeight / 可见视口高度 | 边栏半长与分界 |
| --- | ---: | ---: | ---: |
| 最初 | 606 | 606 | 303 |
| 展开其他分支 | 606 | 681 | 340.5 |
| 再展开分支 | 606 | 684 | 342 |

原实现让 fixed 百分比决定半屏长度，而用户设备上的固定定位参照随内容扩展了。旧测试总让根高度和可见高度一起变化，因此没有覆盖这组实际输入。具体 WKWebView 内部为何产生这种分歧，现有证据不能继续解释；不需要猜测它来定义稳定的布局边界。

`src/viewport.ts` 只读取**当前文档根元素的布局高度**，写入当前卡拥有的一个 CSS 变量。`style.css` 统一计算四块边栏的半长和中线，同时抵消卡片自身的文字缩放。真实窗口/方向变化仍会更新；折叠、揭示答案和滚动不保存、恢复边栏坐标。

适配器通过已有资源作用域管理窗口事件和根元素观察器。卸载后移除监听与 CSS 变量，不增加计时器、全局补丁或业务状态。正反面重新读取当前根高度，不沿用正面的尺寸。

用户用保留完整原字段及图片的私有 alpha.13/14 对照包，在 alpha.14 正面按实际触发步骤展开其他分支后，反馈**「alpha.14 边栏保持稳定」**。这是一次用户报告的 iOS 原卡场景通过；没有收到 alpha.14 数字截图，不能把自动化期望的 303px 写成实机测量。设备系统和 AnkiMobile 版本未提供，其他卡片、所有翻面路径与 Android 仍需日常复测。个人字段、图片和截图均不提交到公开仓库。

## 靠左的折叠圆点缺了一部分

节点圆点在文字左侧，折叠时还画有 4px 外圈。正文需要横向滚动以保留宽表格，但最外层树沿用旧的负偏移后，外圈进入了滚动容器左边界之外。

在 390px 浏览器视口的匿名卡和本地原卡都测到：正文边界为 21px，折叠圆圈左边为 17px。被裁掉的 4px 让它看起来像被边栏挡住。这与边栏高度问题无关。

只把**最外层 node-list** 的左缩进从 28px 调为 38px，为负偏移和外圈留空间，也覆盖模板支持的 2 倍文字缩放。内层仍为 28px，边栏、标题与正文容器的边距不变。文字区域减少 10px，个别长句可能提早换行；没有通过覆盖层级或禁用横向滚动掩盖问题。

## 验证边界

- 官方 Anki 25.9.2 / 26.9.3 构包、独立身份、重复导入、原生 Cloze 与字段/媒体往返检查。
- Chromium / WebKit 的边栏测试把根高度固定为 606，同时把可见高度改为 681/684，再展开分支、翻面、缩放、改变真实根高度并卸载。**这是按用户测量构造的宿主输入测试，不是手机模拟认证。**
- 两种引擎分别检查 320/390px 宽度、正反面、0.5/1/1.1/2 倍缩放的完整圆圈、边栏间距和真实触控点击。
- 完整回归仍覆盖每引擎 100 次生命周期、复杂 HTML、离线、长图和隔离 Desktop 复习。详细结果见 [verification.json](../test-packages/verification.json)。

正常测试包没有布局诊断面板。独立旧版／React 对照包才附带诊断，记录最初正面及当前测量；原版在真实设备上是否也出现相同现象，仍无确认结论。旧包的 `main` 标签指固定旧版 f67c932，现已改为「旧版基线 f67c932」；React 一侧显示实际版本，避免与当前 main 混淆。公开样例和验证不包含任何个人模板安装或同步操作。
